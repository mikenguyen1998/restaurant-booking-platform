# Open questions and pending decisions

Two kinds of item:

- **Business questions (Q-xx):** product rules that are not in the requirements. They
  need a product decision. Where the docs or proposed schema needed a placeholder,
  the placeholder is noted, but it is **not** a decision.
- **Technical decisions (T-xx):** implementation choices for the developer. Each has a
  recommendation that can be accepted or replaced; accepted ones become ADRs in
  [`decisions/`](decisions/README.md).

## Technical decisions

| ID   | Decision                                   | Recommendation                                                                                                                                                                                                       | Alternatives                                                                        |
| ---- | ------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| T-01 | Overlap prevention                         | PostgreSQL `EXCLUDE USING gist` on unreleased allocations (`btree_gist`).                                                                                                                                            | Slot-grid rows with unique `(resource, slot)`; `SERIALIZABLE` isolation with retry. |
| T-02 | Isolation and locking                      | `READ COMMITTED`; restaurant row `FOR KEY SHARE` in bookings vs `FOR UPDATE` in blackout/settings/status changes; resource `FOR KEY SHARE` vs deactivation `FOR UPDATE`; booking `FOR UPDATE` for cancel/reschedule. | `SERIALIZABLE` everywhere (simpler reasoning, more retries).                        |
| T-03 | Trying the next candidate after a conflict | Savepoints inside the transaction (raw `SAVEPOINT` via Prisma `$executeRaw` in an interactive transaction).                                                                                                          | Retry the whole transaction with the conflicting candidate excluded.                |
| T-04 | Idempotency                                | `Idempotency-Key` header (UUID) required on booking creation; stored unique on the booking with a request fingerprint; same key + same fingerprint returns the booking, different fingerprint → 409.                 | Separate `idempotency_keys` table with TTL (useful if more endpoints need it).      |
| T-05 | Money                                      | `bigint` minor units + ISO 4217; `Money` value object; currency exponents from a small table (VND 0, USD 2). Serialise as string in JSON.                                                                            | `numeric(19,4)` + decimal library.                                                  |
| T-06 | Date/time library                          | `Temporal` via a polyfill (`temporal-polyfill`) for zoned date-time and DST rules; native once Node ships it.                                                                                                        | Luxon; date-fns + date-fns-tz.                                                      |
| T-07 | Queue and outbox                           | Transactional outbox table relayed to BullMQ (Redis) by the worker. Delayed jobs for reminders; repeatable jobs for completion/expiry sweeps.                                                                        | pg-boss (PostgreSQL-only queue, no Redis dependency for jobs).                      |
| T-08 | Worker deployment                          | Second entry point (`src/worker.ts`) in `apps/api`, deployed as a separate service.                                                                                                                                  | Separate `apps/worker` sharing code through packages.                               |
| T-09 | Search indexing                            | Outbox-driven incremental indexing + an admin/CLI full reindex using index aliases. Add Elasticsearch to `docker-compose.yml` in Phase 5.                                                                            | Periodic full reindex only.                                                         |
| T-10 | Availability filter in search              | Search in ES without availability, then run the availability engine on the top N hits and drop unavailable ones.                                                                                                     | Precomputed per-slot availability in ES (complex invalidation).                     |
| T-11 | "Opening now" in ES                        | Index weekly opening periods as minute-of-week ranges normalised per restaurant timezone and query with the current minute-of-week per timezone; blackouts applied as a post-filter.                                 | Filter in the API after search.                                                     |
| T-12 | Token transport                            | Short-lived JWT access token (≈15 min) + opaque rotating refresh token stored hashed with family reuse detection; refresh token in an `httpOnly`, `Secure`, `SameSite` cookie.                                       | Both tokens in cookies via a BFF; sessions in Redis.                                |
| T-13 | Password hashing                           | argon2id.                                                                                                                                                                                                            | bcrypt.                                                                             |
| T-14 | API module layering                        | `domain / application / infrastructure / presentation` per module (see [architecture](architecture/README.md#api-internal-layering)).                                                                                | Keep scaffold `controllers/services/...` layout.                                    |
| T-15 | Validation                                 | Zod schemas in `packages/shared` for request/response contracts, shared by web and API.                                                                                                                              | `class-validator` DTOs in the API only.                                             |
| T-16 | Web i18n                                   | `next-intl` with locale-prefixed routes (`/vi`, `/en`), Vietnamese default.                                                                                                                                          | Cookie-based locale without URL prefix.                                             |
| T-17 | Object storage and uploads                 | S3-compatible API; presigned PUT uploads from the browser; API stores keys. Local development: MinIO in docker-compose when photos are implemented (Phase 4/13).                                                     | Upload through the API.                                                             |
| T-18 | Geocoding                                  | `Geocoder` interface only; owners enter coordinates (map picker) in phase 1.                                                                                                                                         | Integrate a provider now.                                                           |
| T-19 | Map rendering                              | MapLibre GL or Leaflet with OpenStreetMap tiles (no API key to start).                                                                                                                                               | Google Maps, Mapbox.                                                                |
| T-20 | PostGIS                                    | Not needed while geo queries run in Elasticsearch.                                                                                                                                                                   | Add PostGIS for DB-side radius queries.                                             |
| T-21 | Localised taxonomy labels                  | `jsonb` per row `{ vi, en }`, validated in the app.                                                                                                                                                                  | Translation table (better once many languages exist).                               |
| T-22 | Booking reference format                   | 8-character Crockford base32, unique, generated with retry on collision.                                                                                                                                             | Sequential numbers per restaurant.                                                  |
| T-23 | Primary keys                               | UUID v7.                                                                                                                                                                                                             | cuid2; bigint identity.                                                             |
| T-24 | Audit log immutability                     | DB trigger blocking UPDATE/DELETE on `audit_logs`, plus no update path in code.                                                                                                                                      | Code convention only.                                                               |
| T-25 | Completion/expiry mechanism                | Periodic sweeper job (every minute) with conditional updates.                                                                                                                                                        | One delayed job per booking.                                                        |
| T-26 | Case-insensitive email                     | Unique index on `lower(email)` and lower-case on write.                                                                                                                                                              | `citext` column type.                                                               |
| T-27 | Rate limiting                              | Redis-backed limiter on auth and booking creation (guest booking is anonymous).                                                                                                                                      | In-memory per instance (not safe with several instances).                           |
| T-28 | Testing concurrency                        | Integration tests against a real PostgreSQL (Testcontainers or the compose database), firing parallel transactions.                                                                                                  | Mocks (cannot test locking).                                                        |
